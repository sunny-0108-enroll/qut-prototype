액터별 통합 흐름누가 · 언제 · 무엇을 파일·문서 흐름AI 에이전트 · 공유드라이브 저장소별 데이터 흐름파일서버 · 구글 드라이브 프로세스 흐름도8단계 · 탱크 견적 트랙 포함
  • 가로는 8단계, 세로는 액터다. 칸 안의 카드가 그 액터가 그 단계에서 하는 일이고, 번호 순서대로 따라가면 전체 흐름이 된다.
  • 카드 아래 → 표시는 다음에 일을 넘겨받는 액터다. ◆ 카드는 판단·승인이다.
  • 카드 왼쪽 위 태그로 처리 주체를 나눴다. H · 승인 처럼 검은 H 태그가 담당자가 직접 처리하는 업무이고(판단·승인 / 작성·입력 / 검토 / 대외 대응 / 관리), AI 자동 시스템 자동은 담당자가 손대지 않는 처리, 외부는 발주처·벤더다.
  • 주황 띠가 있는 카드는 탱크 견적 트랙이다. 위의 버튼으로 일반 견적 / 탱크 견적만 강조해 볼 수 있다.
탱크 견적 원칙 · 참여 결정 후 AI 에이전트가 내부 벤더사 목록에서 분야별 벤더를 골라 항목별로 나눈 예가용 견적 요청을 자동 발송하고, 회신 견적을 자동 취합·비교한다. 담당자는 발송 대상을 확인하고, 비교안을 보고 최적 견적금액과 벤더 후보군을 최종 결정한다. 견적금액은 임원 → 대표이사 순으로 승인한다. 예가를 낸 벤더는 후보일 뿐이고, 수주 후 실제 수행사는 실행 단계에서 따로 정하므로 다를 수 있다.
문서 제어 원칙 · 메일로 들어온 자료는 AI 에이전트가 공유드라이브 일자별 폴더에 올리고, 담당자가 리뷰를 결정하면 견적요청리뷰ID로 문서함에 옮겨 초기 분석을 시작한다. 이후 단계마다 담당자는 단계 폴더를 체크아웃해 임시파일로 작업하고, 체크인하면 AI가 표준 이름·Rev로 폴더링해 저장한다. 분석·견적서는 Rev 단위로 쌓이고, 제출본은 잠긴다. 자세한 규칙은 파일·문서 흐름 탭.
강조

담당자가 처리하는 업무 목록

위 표에서 검은 태그 카드만 모은 것이다. AI·시스템이 만든 결과를 받아 담당자가 결정·작성하는 지점이 여기다.

  • AI 에이전트가 메일과 파일서버(공유드라이브), 담당자의 작업 문서를 어떻게 다루는지 정리한 화면이다.
  • 담당자는 공유드라이브 파일을 직접 고치지 않는다. 단계 폴더를 체크아웃해 작업하고, 체크인하면 AI가 이름·위치·Rev를 맞춰 저장한다.

인터뷰로 확인할 것

  • 일자별 수신 폴더의 실제 경로와 보관 기간, 제외한 메일 자료의 처리
  • 견적요청리뷰ID 형식과 프로토타입의 QP 번호(예: QP-2026-0011)와의 관계
  • 분석 결과를 02_견적참고자료와 03_견적작업 중 어디에 둘지
  • 체크인 때 AI가 정한 위치·이름을 담당자가 확정하는 단계가 필요한지
  • 같은 업무 흐름(메일 → 일자별 정리 → 리뷰 결정 → 문서함 → 체크아웃·체크인 → 제출 잠금)을 사내 파일서버로 구현할 때와 구글 드라이브(공유 드라이브)로 구현할 때, 데이터가 어디서 어디로 무엇이 오가는지 그렸다.
  • 선 위 글자가 오가는 데이터와 방법이다. 초록 박스는 파일이 놓이는 위치, 회색 박스는 견적 AI DB에 남는 기록이다.
  • 두 방식의 차이는 아래 비교표에 모았다.

인터뷰로 확인할 것

  • 현재 회사 메일이 사내 메일서버인지 Google Workspace(Gmail)인지
  • 견적 자료를 클라우드에 둘 수 있는지 (발주처 보안 조건 포함)
  • 담당자가 엑셀 원본(.xlsx)으로 작업하는지, 구글 시트로 바꿔도 되는지 — 드라이브 방식의 체크아웃·리비전 방식이 달라짐

  • 공사 견적 AI의 8단계 프로세스 흐름이다.
  • AI 처리(문서를 읽고 판단하거나 초안을 만듦)와 시스템(등록·저장·계산·이력처럼 정해진 규칙대로 처리)을 다른 레인으로 나눠, AI가 어디에 들어가는지 보이게 했다.
  • '보류' 박스는 지금 프로세스에 없어도 되는 기능이라 상세 정리에서 뺀다.
  • 탱크 견적 트랙: 대표가 참여를 결정하면 AI 에이전트가 내부 벤더사 목록에서 분야별 벤더를 골라 항목별 견적 요청을 자동으로 보내고, 받은 견적을 자동 취합·비교한다. 최적 견적금액과 벤더 후보군의 최종 결정은 탱크 견적담당자가 하고 견적서를 작성한다. 견적금액은 임원 → 대표이사 순으로 승인받는다 (주황 테두리 박스).
  • 예가를 낸 벤더는 후보군일 뿐이다. 수주 후 실제 수행사는 실행 단계에서 따로 정하며, 예가 벤더와 다를 수 있다.
  • 알림은 공통 기반 기능이라 박스로 그리지 않았다.
  • 01단계는 메일 → 공유드라이브 일자별 폴더 → 담당자 리뷰 결정 → 견적요청리뷰ID → 문서함 순서다. 파일 저장 규칙은 파일·문서 흐름 탭.
  • 박스를 누르면 메뉴가 열린다 — 상세 설계(그 박스의 기능·정책), 화면 프로토타입(그 단계 화면), 검토 자료(그 단계의 인터뷰·기술 검증 항목).
